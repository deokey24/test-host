# 모바일 배너 이미지 제작 규격 (상단배너 / 중간배너)

> 이 문서는 **다른 작업 세션에 그대로 전달하는 작업 지시서**다.
> 원본(데스크톱) 이미지는 `docs/mobile-banner-source/`에 있고, 원격에서도 받을 수 있다:
> `https://dockteacher.co.kr/uploads/site/content-banner/top/<uuid>.png`

## 1. 왜 필요한가

홈 상단/중간 배너 원본이 **1280×180(7.1:1)**, **1280×100(12.8:1)** 로 극단적으로 납작하다.
모바일(폭 390px)에서 이 비율을 그대로 폭에 맞추면 높이가 **55px / 30px** 밖에 안 돼 글자를 읽을 수 없다.

그래서 사이트는 **모바일 전용 이미지가 등록돼 있으면 폭 600px 이하에서 그 이미지로 교체**한다.
등록돼 있지 않으면 원본을 확대 크롭해서 보여주는데, 이때 좌우가 잘려나간다(상단 40% / 중간 72% 손실).
→ **모바일 전용 이미지를 만드는 목적은 "잘림 없이, 글자를 크게"** 다.

## 2. 출력 규격 (필수)

| | 상단배너 | 중간배너 |
|---|---|---|
| **크기** | **1080 × 720 px** | **1080 × 400 px** |
| 비율 | 3:2 | 2.7:1 |
| 필요 개수 | 4개 (아래 4-1~4-4) | 1개 (4-5) |
| 390px 화면에서의 높이 | 260px | 144px |
| 형식 | PNG (또는 JPG 품질 85) | 동일 |
| 색공간 | sRGB | sRGB |
| 파일 용량 | 500KB 이하 권장 | 300KB 이하 권장 |

### 반드시 지킬 것

1. **같은 종류의 배너는 픽셀 크기까지 완전히 동일하게.**
   상단배너 4개는 전부 정확히 1080×720이어야 한다. 슬라이더 높이는 슬라이드 중 가장 세로가 긴 이미지를 기준으로 잡히므로, 하나라도 비율이 다르면 나머지 배너에 위아래 여백(레터박스)이 생긴다.

2. **배경을 이미지 가장자리까지 꽉 채운다.** 투명 영역·흰 여백 금지.
   배너는 화면 좌우 끝까지 닿게 표시되므로, 가장자리에 여백이 있으면 그대로 화면에 보인다.

3. **비율 상한을 넘기지 말 것.** 상단은 2.6:1, 중간은 3.6:1 보다 납작해지면 코드가 좌우를 잘라낸다.
   1080×720(1.5:1), 1080×400(2.7:1)은 둘 다 상한 안쪽이라 안전하다.
   (상한값은 `public-figma/index.html`의 `BANNER_MOBILE_MAX_RATIO`)

4. **원본의 색·서체·톤을 그대로 유지한다.** 배치만 바꾸는 작업이고, 리디자인이 아니다.

## 3. 레이아웃 규칙

### 안전 영역
가장자리에서 **5%** 안쪽(상단배너 기준 상하 36px / 좌우 54px)에는 텍스트·로고를 두지 않는다.

### 최소 글자 크기
1080px 이미지가 390px 폭에 들어가므로 축소율은 **0.361배**다. 이미지 상의 크기 × 0.361 = 실제 화면 크기.

| 역할 | 이미지 상 크기 | 화면에서 보이는 크기 |
|---|---|---|
| 메인 헤드라인 | 90 ~ 120px | 33 ~ 44px |
| 서브 헤드라인 | 48 ~ 60px | 17 ~ 22px |
| 본문·정보 | 40 ~ 48px | 14 ~ 17px |
| **절대 최소** | **36px** | 13px |

36px 미만은 모바일에서 읽을 수 없으므로 쓰지 않는다. 원본에서 작게 들어간 부가정보는 **글자를 키우거나, 과감히 빼는 쪽**을 택한다.

### 가로 1줄 → 세로 스택 재배치
원본은 전부 `로고 | 헤드라인 | 정보 | CTA` 를 **좌→우 한 줄**로 늘어놓은 구조다.
모바일에서는 이걸 **위→아래**로 다시 쌓는다:

```
┌──────────────────────┐
│      [로고 (작게)]     │  ← 상단, 높이의 10~15%
│                      │
│    메인 헤드라인 1줄    │  ← 2~3줄로 줄바꿈, 가장 크게
│    메인 헤드라인 2줄    │
│                      │
│   [부가 정보 / 날짜]    │
│                      │
│   [ CTA 버튼 풀폭 ]    │  ← 있는 배너만
└──────────────────────┘
```

- 배경 사진(대학 건물 등)은 **잘라내지 말고** 세로 구도에 맞게 재배치하거나, 톤 오버레이를 유지한 채 전체 배경으로 확장한다.
- 원본에서 좌우로 벌어져 있던 구분선(`|`)은 세로 배치에서 없애거나 가로 구분선으로 바꾼다.
- 가운데 정렬을 기본으로 한다(원본의 좌측 정렬을 그대로 가져오면 세로 구도에서 비어 보인다).

## 4. 배너별 작업 지시

### 4-1. 상단 1 — `top-1-8월신규반.png` (1280×180 → 1080×720)
현재 구성(좌→우): DOCK PASS 로고 / "연고대 논술 대비 **8월 신규반 안내**" / 정보박스 "방학특강반 D반 | 개강 8월 1일(토) | 화 13-16시, 토 14-17시" / 파란 버튼 "자세한 내용 확인하기 >" / 우측 연세대 건물 사진 + 원형 배지 "★★★★★ 마지막 최종 충원 기간". 배경 흰색/연회색.

재배치:
1. 상단에 DOCK PASS 로고 + "독편사편입논술학원"
2. "마지막 최종 충원 기간" 원형 배지 → 헤드라인 위 **가로 알약형 배지**로 변환
3. 헤드라인 "연고대 논술 대비" / "**8월 신규반 안내**" 2줄 (8월 신규반 안내는 파란색 유지)
4. 정보박스는 3줄로 세로 스택: "방학특강반 D반" / "개강 8월 1일(토)" / "화 13-16시, 토 14-17시"
5. 하단에 "자세한 내용 확인하기 >" 버튼 **풀폭**
6. 연세대 건물 사진은 배경 우하단에 흐리게 깔거나 생략

### 4-2. 상단 2 — `top-2-연세대대관.png` (→ 1080×720)
현재: 배경 연세대 건물(진한 네이비 톤) / "실전처럼, 연세대에서!" (양옆 장식선) / "**연세대** 대관 모의논술" (연세대=흰색, 나머지=하늘색) / 흰 박스 "11월 초 / 시행 예정" / 우측 DOCK PASS 로고.

재배치:
1. 배경: 연세대 건물을 세로 구도로 재배치, 네이비 그라데이션 오버레이 유지
2. "실전처럼, 연세대에서!" (장식선은 짧게)
3. "**연세대**" / "대관 모의논술" 2줄 — 가장 크게
4. 흰 박스 "11월 초 시행 예정" 가로형으로
5. 하단에 DOCK PASS 로고 + "독편사편입논술학원"

### 4-3. 상단 3 — `top-3-고려대대관.png` (→ 1080×720)
4-2와 **완전히 같은 레이아웃**으로. 다른 점은 크림슨/버건디 톤 + 고려대 건물 사진 + "고려대" 텍스트뿐이다. 두 배너가 슬라이더에서 연달아 보이므로 구도가 일치해야 한다.

### 4-4. 상단 4 — `top-4-dockpass신설.png` (→ 1080×720)
현재: 검정~네이비 배경 / 좌측 DOCK PASS 로고 / "독편사편입논술학원의 새로운 브랜드" / "**dockpass 홈페이지 신설!**" / "편입논술, dockpass에서 시작됩니다." / 우측 노트북 목업(사이트 화면) + 청색 광선 효과.

재배치:
1. 상단 DOCK PASS 로고
2. "독편사편입논술학원의 새로운 브랜드" (파란색 유지)
3. "dockpass 홈페이지 **신설!**" 1~2줄 — 가장 크게
4. "편입논술, dockpass에서 시작됩니다."
5. 하단에 노트북 목업 — 화면 안 텍스트는 어차피 안 읽히므로 크게 넣거나 실루엣으로 처리
6. 청색 광선 효과는 배경으로 유지

### 4-5. 중간 1 — `mid-1-합격자88명.png` (1280×100 → 1080×400)
현재: 네이비 배경 + 파란 색종이 / DOCK PASS 로고 | "2026학년도 / **최종합격자** / 월계관 **88명**" | "1차 합격자 / **222명**" | 트로피 일러스트. **원본이 12.8:1로 가장 납작해서 크롭 폴백 시 손실이 가장 크다 — 우선순위 1순위.**

재배치 (2줄 구성 권장):
```
┌──────────────────────────────┐
│  [DOCK PASS]      2026학년도   │
│   🏆   최종합격자  ⟨88명⟩       │  ← 88명을 가장 크게
│        1차 합격자 222명         │
└──────────────────────────────┘
```
1. "2026학년도 최종합격자" + 월계관 감싼 "**88명**" 을 메인으로 크게
2. "1차 합격자 222명" 은 그 아래 한 줄
3. DOCK PASS 로고와 트로피는 좌우 또는 상하 코너에 배치
4. 색종이·반짝임 효과는 배경으로 유지

## 5. 납품 전 검수 체크리스트

- [ ] 상단배너 4개가 **모두 정확히 1080×720** (1px도 다르면 안 됨)
- [ ] 중간배너가 **정확히 1080×400**
- [ ] 이미지를 **390px 폭으로 축소**해서 봤을 때 메인 헤드라인·핵심 숫자가 읽히는가
- [ ] 가장 작은 글자가 이미지 상 36px 이상인가
- [ ] 가장자리에 투명 영역이나 의도치 않은 흰 여백이 없는가
- [ ] 4-2와 4-3의 구도가 서로 일치하는가
- [ ] 원본의 색상·서체·브랜드 톤이 유지됐는가
- [ ] 파일 용량이 상단 500KB / 중간 300KB 이하인가

## 6. 등록 방법

관리자(`/admin`) → **배너 관리** → 상단배너 또는 중간배너의 해당 항목 **수정** →
**"모바일 이미지"** 슬롯에 업로드 → 저장.

- 모바일 이미지를 지우고 싶으면 "모바일 이미지 없이 쓰기" 버튼 → 원본 확대 크롭으로 되돌아간다.
- "확대 크롭 시 남길 부분"(왼쪽/가운데/오른쪽)은 모바일 이미지가 **없을 때만** 적용된다.
- 콘텐츠배너(DOCK NEWS)·사이드배너에는 모바일 이미지 슬롯이 없다(원본이 600×325, 320×325로 이미 세로가 충분해 문제없음).

> 등록 전 DB 마이그레이션이 필요하다: `infra/schema.sql` 하단의 `ALTER TABLE content_banners`
> (`mobile_image_url`, `mobile_focus` 컬럼). 미적용 상태에서 저장하면 안내 메시지가 나온다.
