# 계획: 유입 키워드·페이지 경로·체류시간을 결제와 연결하기

작성일: 2026-10-14 · 작성자: Fable(계획) · 선행: `analytics-and-server-conversion.md`(1·4번, 구현 중), `marketing-meeting-prep.md` 3-5(한계 정리)
답하려는 질문: ① 네이버·구글 등에서 **어떤 키워드**로 들어와 결제했나 ② **어떤 페이지를 보고/머물다** 결제했나 ③ **어떤 페이지에 얼마나 머물렀나**

## 0. 결론 요약
- ③ 체류시간과 ② 페이지 흐름의 "전체 방문자 평균"은 **GA4가 자동으로 준다**(1번 작업으로 GTM이 깔리면 설정만). 개발 0.
- ①·② 를 **"결제한 그 사람" 단위로 우리 DB에 남기는 것**이 이번 개발의 핵심이다: 첫 방문 시 유입 정보(UTM·리퍼러·랜딩·광고 키워드 파라미터)와 **결제 직전까지 본 페이지 경로**를 퍼스트파티 쿠키에 모아, 가입·결제 시점에 `members`/`payments`에 저장하고 관리자 집계 화면으로 본다.
- 키워드의 한계(3-5 재확인): 오가닉 검색은 검색엔진이 검색어를 안 넘겨서 **사람 단위 키워드는 검색광고 클릭만** 가능. 오가닉은 "랜딩페이지 단위" + 서치콘솔/서치어드바이저 "검색어별 클릭 합계" + 가입폼 키워드 선택지로 근사한다.

## 1. 질문별 데이터 소스 매핑
| 질문 | 자동(GA4/도구) | 우리 DB에 쌓을 것(개발) | 사람 단위 가능? |
|---|---|---|---|
| ① 어떤 키워드로 왔나 | GA4 세션 소스/매체, 서치콘솔·서치어드바이저(검색어별 노출·클릭 합계), 네이버 애널리틱스 검색어(일부) | 첫 방문·마지막 방문의 `utm_*`, `referrer`, `landing_page`, 네이버 검색광고 `n_query/n_keyword/n_ad_group/n_media`, 구글 `gclid`, 가입폼 키워드 선택지 | 광고 클릭: ✅ / 오가닉: 랜딩페이지·가입폼 근사 |
| ② 어떤 페이지 보고 결제했나 | GA4 경로 탐색·퍼널 탐색(vodDetail→orderConfirm→paymentComplete), 랜딩페이지별 전환율 | 결제 직전 세션의 **페이지 경로(최근 20개, 각 체류초)** 를 `payments.client_context.journey`에 저장, 회원별 `last_landing_page` | ✅ (결제 행마다 경로가 붙음) |
| ③ 어디에 얼마나 머물렀나 | GA4 "페이지별 평균 참여시간", Clarity 히트맵·세션 녹화·스크롤 깊이 | journey의 페이지별 체류초(결제자만) | 전체: 익명 평균 / 결제자: ✅ |

## 2. 구축 항목

### 2-A. 퍼스트파티 어트리뷰션 쿠키 + 서버 저장 (개발 핵심, 2~3일)
- **클라이언트** `public-figma/analytics.js`에 추가(1번 작업 파일 재사용):
  - 첫 방문 시 `dt_attr`(쿠키, 90일, `SameSite=Lax`)에 `first`={`ts`, `landing`, `referrer`, `utm_source/medium/campaign/content/term`, `gclid`, `n_query`, `n_keyword`, `n_ad_group`, `n_media`, `n_rank`} 저장. 이후 방문에 UTM/광고 파라미터가 있으면 `last`를 갱신(first는 유지). 값은 각 100자 절단, URL 디코딩.
  - 세션 경로 `dt_journey`(sessionStorage): 페이지 진입마다 `{path, q(id 등 쿼리 일부), t_in}` push, 떠날 때(`visibilitychange`/`pagehide`) 체류초 기록. 최근 20개 유지. 결제 페이지에 로그인 모달 등 SPA 전환은 없으므로 페이지 단위로 충분. PayUp 결제창(외부 도메인)으로 갔다 돌아와도 sessionStorage는 같은 탭이면 유지.
  - `/api/payments/init`·`/api/members/signup` fetch 바디에 `attribution: {first,last}`, `journey: [...]`를 함께 보낸다(쿠키만 믿지 않고 바디로도 보내는 이유: 서버가 쿠키 파싱 없이 JSON 그대로 저장, 크기 제한 회피).
- **서버**
  - `payments.client_context`(1·4번에서 추가 중인 JSON 컬럼)에 `attribution`·`journey` 필드를 **추가**로 담는다 → 새 컬럼 없음. 서버에서 길이 상한(journey 20개, 전체 8KB) 검증.
  - `members`에 `signup_context TEXT NULL`(JSON: attribution + journey + `ua`) 1컬럼 추가. 기존 `signup_channel/search_keyword/referrer_code`는 유지. 스키마 변경 → 운영 DB ALTER 1회.
  - 집계 편의를 위해 `payments`·`members`에 생성 컬럼은 두지 않고, 집계 SQL에서 `JSON_EXTRACT`(MySQL 5.7+) 사용. DB 버전이 5.7 미만이면 집계 시 Node에서 파싱(구현 시 `SELECT VERSION()` 확인).
- **GA4 연결**: 로그인·가입 시 `dataLayer`에 `user_id`(회원 id)를 실어 GTM GA4 구성 태그에 매핑 → GA4에서도 크로스디바이스 일부 봉합, 우리 DB의 `member_id`와 GA4 탐색 결과를 대조 가능.

### 2-B. 가입폼 보강 (0.5일)
- 가입경로 체크박스에 `인스타그램 / 유튜브 / 네이버 블로그 / 카카오톡 채널` 추가(`join.html:199-206`).
- "인터넷 검색" 선택 시 검색키워드 **선택지 + 직접입력**(편입논술 / 연고대 편입 / 한예종 논술 / 독편사 / 기타)으로 바꾸고 필수화(`join.html:212-213`). 저장 로직은 그대로(`search_keyword`).
- `dt_attr`에 UTM이 있으면 해당 채널 체크박스를 **자동 선택**(사용자 기억 의존 완화).

### 2-C. 관리자 "유입·전환 분석" 탭 (1.5~2일, `admin/`)
- 기간 필터(기본 30일) + 표 4개:
  1. **채널별**(first.utm_source/medium → 없으면 referrer 도메인 분류: naver/google/instagram/youtube/kakao/direct): 가입 수, 결제 수, 매출, 결제 전환율.
  2. **키워드별**: `n_query`/`utm_term`/가입폼 `search_keyword` 합쳐서 가입·결제·매출.
  3. **랜딩페이지별**: `first.landing` 기준 가입·결제·매출(오가닉 키워드 근사의 핵심 표).
  4. **결제 직전 페이지 TOP**: journey 마지막 3개 페이지 빈도·평균 체류초.
- 결제 상세 모달에 "유입 → 경로(페이지·체류초) → 결제" 타임라인 표시. 회원 상세에 가입 시 유입 정보 표시.
- CSV 내보내기(채널·키워드 표).

### 2-D. GA4·Clarity 설정 (개발 0, 운영 문서 0.5일)
- GA4: 서치콘솔 연결(검색어→랜딩페이지 리포트), 탐색 분석 3개 템플릿 저장(퍼널: vod→vodDetail→orderConfirm→paymentComplete / 경로 탐색: purchase 역추적 / 랜딩페이지별 전환), 전환 이벤트 `purchase`·`sign_up` 지정, `user_id` 리포팅 ID 설정. "페이지별 평균 참여시간"이 ③의 전체 방문자 답.
- Clarity: 히트맵·녹화로 "어디서 멈추고 이탈하는지" 정성 확인. GA4 연동으로 세션 대조.
- 네이버: 서치어드바이저(검색어별 클릭), 네이버 애널리틱스(유입 검색어 리포트). 검색광고 집행 시 광고 URL에 `n_query` 등 추적 파라미터 자동삽입 옵션 ON + 전환 스크립트를 GTM에 추가.
- `docs/analytics-setup.md`(1번 작업에서 생성)에 위 내용 절 추가.

### 2-E. 선택: 자체 페이지뷰 로그 테이블 (권장 안 함)
모든 방문자의 페이지뷰·체류를 `page_views` 테이블에 쌓으면 비회원 체류도 DB에서 보이지만, 월 수십만 행·개인정보(행태정보) 처리·GA4와 중복. GA4+Clarity로 충분하므로 **보류**. 필요해지면 회원 로그인 세션만 대상으로 축소해 재검토.

## 3. 질문별 "어떻게 답이 나오나" (구축 후)
- "네이버에서 '한예종 논술'로 검색해 들어와 결제한 사람이 몇 명?" → 검색광고면 관리자 키워드 표(`n_query`)에서 바로. 오가닉이면 서치어드바이저 클릭 합계 × 관리자 랜딩페이지별 결제율 + 가입폼 키워드 표로 근사.
- "결제한 사람들은 결제 전에 어떤 페이지를 봤나?" → 관리자 "결제 직전 페이지 TOP" 표, 결제 상세 타임라인. 전체 흐름은 GA4 경로 탐색.
- "상세페이지에 보통 얼마나 머무나, 머문 사람이 더 결제하나?" → GA4 페이지별 참여시간(전체) + 관리자 journey 체류초(결제자) 비교. Clarity로 어느 구간에서 이탈하는지.

## 5. 한계·법무
- 오가닉 검색어는 사람 단위 불가(검색엔진 정책). 크로스디바이스·시크릿·쿠키 삭제 시 first 유실. 설치일 이후 데이터만.
- journey·attribution은 행태정보 → 개인정보처리방침에 "서비스 이용기록(방문 페이지·체류시간·유입경로)" 수집 항목과 보유기간(예: 탈퇴 시 삭제, 회원 삭제 시 `client_context`는 결제기록 보존 범위에서 익명화 대상에 포함) 명시 필요. 회원 삭제 로직(`DELETE /admin/api/members/:id`)에서 `signup_context` NULL 처리 추가.
